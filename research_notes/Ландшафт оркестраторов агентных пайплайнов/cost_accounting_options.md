# Cost accounting and enforcement options for an orchestrator running Claude Code / Codex sessions as pipeline nodes (as of 2026-10-15)

Scope note: most facts below come from primary vendor docs fetched 2026-10-15 (code.claude.com, platform.claude.com, learn.chatgpt.com / developers.openai.com, docs.litellm.ai, portkey.ai, docs.helicone.ai, developers.cloudflare.com, docs.paperclip.ing, github.github.com/gh-aw). Items marked **[secondary]** come from third-party blogs/READMEs and should be verified against a live install. Items marked **[uncertain]** are inferences or things I could not confirm.

## Q1. What usage/cost data does Claude Code emit per run under subscription auth vs API-key auth? Is `total_cost_usd` meaningful on subscription auth? What does `--max-budget-usd` do? Does `costBasis` exist?

### Takeaway
Claude Code emits the same client-side USD *estimate* regardless of auth method: it multiplies token counts by a bundled list-price table (or a managed `modelPricing` table). On subscription auth the number is produced but "isn't relevant for billing"; the real constraint there is the 5-hour/weekly usage window exposed via `anthropic-ratelimit-unified-*` headers, not dollars. `--max-budget-usd` enforces against this same estimate in `-p` mode on any auth. `costBasis` exists (`list` | `managed` | `unknown`) on each `modelUsage` entry since v2.1.246.

### Cited Findings

**Result JSON / Agent SDK fields**
- The `result` message (TypeScript `SDKResultMessage`, Python `ResultMessage`) carries `total_cost_usd`, cumulative `usage`, and `modelUsage` (per-model map). "The `total_cost_usd` and `costUSD` fields are client-side estimates, not authoritative billing data. The SDK computes them locally from a price table bundled at build time, unless a `modelPricing` table is in effect. They can drift from what you are actually billed when: pricing changes; the installed SDK version does not recognize a model; billing rules apply that the client cannot model." — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- "Use these fields for development insight and approximate budgeting. For authoritative billing, use the Usage and Cost API or the Usage page in the Claude Console. Do not bill end users or trigger financial decisions from these fields." — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Subagent inclusion differs per field: `usage` = "Excluded. Counts only the top-level agent loop"; `total_cost_usd` = "Included. Counts subagent requests alongside the top-level loop"; `modelUsage` = "Included … broken down by model". Recommendation: "Use `modelUsage` … for whole-tree token accounting; the `usage` field undercounts as soon as nesting occurs." — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- `ModelUsage` type (verbatim): `inputTokens, outputTokens, thinkingTokens?, cacheReadInputTokens, cacheCreationInputTokens, webSearchRequests, costUSD, contextWindow, maxOutputTokens, canonicalModel?, provider?, costBasis?: 'list' | 'managed' | 'unknown'`. `provider` values: `firstParty`, `bedrock`, `vertex`, `foundry`, `anthropicAws`, `mantle`, `gateway`. "`costBasis` names the price table that priced the model's latest request: `list` for list price, `managed` for a `modelPricing` table, or `unknown` when neither matched the model ID. The field requires Claude Code v2.1.246 or later." — [TypeScript SDK reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Per-step `output_tokens` on assistant messages "is a placeholder" (the `message_start` count); read real output tokens from the result's `usage`/`modelUsage`. Parallel tool calls share a `message.id`, so dedupe by id. — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Error results: `error_max_budget_usd` — "`usage` leaves out the response that crossed the budget, while `total_cost_usd` and `modelUsage` include it." `error_during_execution` after a crash — "every cost field may be zeroed." — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Resume semantics (important for per-node accounting): "Calls that resume the same session: Claude Code saves the session's totals to its transcript when the process exits normally and restores them when a later call resumes or forks the session. Each result already includes the session's earlier spend. … Before v2.1.277, a session that you resumed through the SDK or `claude -p` started its totals at zero." — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Data-residency rule the client *does* model: when a response reports `inference_geo: "us"`, list price × 1.1 (SDK ≥ TS 0.3.239 / Py 0.2.144). — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

**Subscription vs API auth**
- "The Session block in `/usage` shows API token usage and is intended for API users. Claude Max and Pro subscribers have usage included in their subscription, so the session cost figure isn't relevant for billing purposes." — [Manage costs](https://code.claude.com/docs/en/costs)
- "Claude Code computes the dollar figure locally from token counts at list price, unless a `modelPricing` table is in effect. … The figure is an estimate, so for authoritative billing see the Usage page in the Claude Console." — [Manage costs](https://code.claude.com/docs/en/costs)
- On Teams/Enterprise: "Usage inside the seat allowance isn't metered in dollars." Spend report covers usage-credit (overage) spend only. — [Manage costs](https://code.claude.com/docs/en/costs)
- Subscription usage windows: "a per-seat allowance that resets on a rolling five-hour window and a weekly window … shared with Claude chat and Cowork". Limit-hit messages: "You've hit your session limit"/"weekly limit" (seat window), vs "individual spend limit"/"org's monthly spend limit" (usage credits). — [Manage costs](https://code.claude.com/docs/en/costs)
- Prompt-cache TTL differs by auth: "The lifetime is an hour on a subscription and drops to five minutes once you're drawing on usage credits; on an API key or cloud provider, it's five minutes by default." — [Manage costs](https://code.claude.com/docs/en/costs). This changes the *actual* cost basis of the same token counts across auth modes.
- `claude auth status` prints JSON with `authMethod` ∈ `none`, `claude.ai`, `oauth_token`, `api_key`, `api_key_helper`, `third_party` — an orchestrator can use this to tag each node's billing class. — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- `claude setup-token` generates a long-lived OAuth token for CI "Requires a Claude subscription." — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- Anthropic announced (May 13 2026) then paused a plan to move Agent SDK / `claude -p` / third-party usage to a separate monthly credit; support page reportedly states "For now, nothing has changed: Claude Agent SDK, claude -p, and third-party app usage still draw from your subscription's usage limits." **[secondary]** — [The New Stack](https://thenewstack.io/anthropic-pauses-claude-agent-sdk-subscription-change/); [letsdatascience](https://letsdatascience.com/news/anthropic-pauses-claude-agent-sdk-billing-overhaul-1cff2071)
- Gateway response headers: "`anthropic-ratelimit-unified-*` — Forward the upstream's values unchanged on every response. Claude Code reads them on successful responses to show usage against plan limits to developers signed in with claude.ai, and on a `429` to tell a plan limit or spend cap from a temporary throttle." — [Gateway compatibility guide](https://code.claude.com/docs/en/llm-gateway-protocol). This is the only machine-readable "remaining quota" signal for subscription auth I found; it is not surfaced in the `-p` result JSON (gap below).

**`--max-budget-usd`**
- "`--max-budget-usd` — Stop the run once estimated spend on API calls reaches this amount (print mode only). Claude Code checks the cap against its client-side cost estimate, which can differ from your bill. Spend from subagents counts toward the cap. Spend can pass the cap, so leave headroom. When you return to a conversation with `--continue` or `--resume`, totals restored from earlier runs don't count toward it. Once spend reaches the cap, spawning another subagent fails with `Budget limit reached`, and Claude Code stops background subagents that are still running; the cap-enforcement behaviors require Claude Code v2.1.217 or later." — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- The 1.1× data-residency-multiplied figure "also counts toward `--max-budget-usd`"; a managed `modelPricing` table is applied to this limit too. — [Manage costs](https://code.claude.com/docs/en/costs); [Settings reference](https://code.claude.com/docs/en/settings-reference)
- SDK `maxBudgetUsd`: "Stop the query when the client-side cost estimate reaches this USD value. The estimate can pass this value, so leave headroom. Counts only the call's own spend." A `/clear` in streaming-input mode resets the budget. — [TypeScript SDK reference](https://code.claude.com/docs/en/agent-sdk/typescript); [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- `--max-turns` — "Limit the number of agentic turns (print mode only). Exits with an error when the limit is reached. No limit by default." — [CLI reference](https://code.claude.com/docs/en/cli-reference)

**`modelPricing` (contracted rates)**
- Managed-settings-only key (ignored in user/project/local settings and `--settings`), v2.1.242+. Shape: `{"modelPricing": {"multiplier": 0.85, "overrides": {"claude-sonnet-4-6": {"input": 2.4, "output": 12, "cacheRead": 0.24, "cacheWrite": 3}}}}`; `multiplier` is (0, 10]; override rates are USD per million tokens, all four required; `cacheWrite` covers both 5m and 1h writes. "The setting changes what Claude Code reports, not what Anthropic charges." — [Settings reference](https://code.claude.com/docs/en/settings-reference); [Manage costs](https://code.claude.com/docs/en/costs)
- A host embedding Claude Code via the SDK can supply the table through `managedSettings` only when `CLAUDE_CODE_PROVIDER_MANAGED_BY_HOST` is set (v2.1.246+). — [Settings reference](https://code.claude.com/docs/en/settings-reference)

**OpenTelemetry**
- Enable with `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `OTEL_METRICS_EXPORTER=otlp|prometheus|console`, `OTEL_LOGS_EXPORTER=otlp|console`, `OTEL_EXPORTER_OTLP_PROTOCOL`, `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_HEADERS`; `OTEL_METRIC_EXPORT_INTERVAL` default 60000 ms, `OTEL_LOGS_EXPORT_INTERVAL` default 5000 ms. — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Metrics: `claude_code.cost.usage` (USD, "incremented after each API request"), `claude_code.token.usage` (tokens; attribute `type` ∈ `input`, `output`, `cacheRead`, `cacheCreation`; "The `input` type excludes cache tokens"), `claude_code.session.count`, `claude_code.lines_of_code.count`, `claude_code.commit.count`, `claude_code.pull_request.count`, `claude_code.code_edit_tool.decision`, `claude_code.active_time.total`. Cost/token attributes: `model`, `query_source` (`main`/`subagent`/`auxiliary`), `speed`, `effort`, `agent.name`, `skill.name`, `plugin.name`, `mcp_server.name`, `mcp_tool.name`. — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Standard attributes: `session.id` (default on), `organization.id`, `user.account_uuid`, `user.account_id`, `user.id` ("Random anonymous identifier stored in `~/.claude.json`. Not derived from your Claude account."), `user.email`, `terminal.type`, `app.entrypoint` (`cli`/`sdk-ts`, default off), `app.version` (default off), plus any `OTEL_RESOURCE_ATTRIBUTES` keys (default on). — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Event `claude_code.api_request` fields: `model`, `cost_usd` ("Estimated cost in USD"), `cost_usd_micros` (integer), `duration_ms`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`, `request_id`, `client_request_id`, `speed`, `query_source`, `effort`. Events also carry `prompt.id`, `workspace.host_paths`, `workflow.run_id`, `workflow.name` ("never attached to metrics because they would cause unbounded cardinality"). — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Custom attribution: `export OTEL_RESOURCE_ATTRIBUTES="department=engineering,team.id=platform,cost_center=eng-123"` — "added to every metric datapoint and event"; no spaces in values; custom keys cannot override standard ones. — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Operational constraints: "Claude Code ignores OTel exporter variables in a repository's `.claude/settings.json`" (only env/managed settings can enable telemetry); "Claude Code doesn't pass `OTEL_*` variables to subprocesses such as the Bash tool, hooks, or MCP servers." — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- "OpenTelemetry export works on every setup and is the only option that streams per-user token and cost metrics into your own observability stack in near real time." By default "Claude Code computes every cost figure it shows developers at list price, so if your organization pays contracted rates, the figures in `/usage`, the status line, and OpenTelemetry don't match your bill." — [Manage costs](https://code.claude.com/docs/en/costs)

**Server-side per-user reporting (Anthropic-hosted only)**
- Claude Code Analytics API `GET /v1/organizations/usage_report/claude_code?starting_at=YYYY-MM-DD` returns one record per actor per day: `actor` (`user_actor.email_address` or `api_actor.api_key_name`), `customer_type` (`api` | `subscription`), `terminal_type`, `core_metrics` (`num_sessions`, `lines_of_code.added/removed`, `commits_by_claude_code`, `pull_requests_by_claude_code`), `tool_actions`, `model_breakdown[]` with `tokens.{input,output,cache_read,cache_creation}` and `estimated_cost.{currency:"USD", amount}` in **cents**. "Metrics are available with up to 1-hour delay." "This API only tracks Claude Code usage on the Claude API" (not Bedrock/Foundry/Vertex/Claude Platform on AWS). Admin API key required; unavailable to individual accounts. — [Claude Code Analytics API](https://platform.claude.com/docs/en/manage-claude/claude-code-analytics-api)
- When a gateway credential or `apiKeyHelper` is active, "Claude Code doesn't report usage metrics to the Console analytics dashboard" (v2.1.246+). — [Connect to an LLM gateway](https://code.claude.com/docs/en/llm-gateway-connect)

### Inferences
- The `total_cost_usd` field is *always populated* (it is a pure client-side computation from tokens × price table) and is therefore a usable, comparable "list-price-equivalent" number across subscription, API-key, Bedrock/Vertex and gateway nodes — but it is a cost *proxy*, never a charge, and for subscription nodes it has no billing meaning at all.
- `costBasis` + `provider` + `canonicalModel` on `modelUsage` give an orchestrator enough metadata to decide whether to trust the harness number (`list`/`managed`) or re-price from tokens (`unknown`).
- Per-node accounting under `--resume` must read the *latest* result's totals rather than summing results (v2.1.277+), or disable resume and give each node its own session.
- `--max-budget-usd` is a soft cap ("Spend can pass the cap") that works identically on subscription auth; on subscription nodes it caps *list-price-equivalent consumption*, which is a reasonable proxy for how fast the seat's usage window is being consumed, but it is not the window itself.

### Gaps
- Headless mode has no documented way to read the subscription's remaining 5-hour/weekly window from the `-p` result JSON or stream; only interactive `/usage` and the `anthropic-ratelimit-unified-*` headers (visible to a gateway) expose it. I found no official schema for those headers.
- I did not find the exact list of `SDKResultMessage.subtype` values in the fetched portion of the TypeScript reference (the page is ~290 KB); `success`, `error_max_turns`, `error_max_budget_usd`, `error_during_execution` are confirmed by the cost-tracking page; others (e.g. `error_max_structured_output_retries`) are **[uncertain]**.
- Whether the bundled price table (and therefore `total_cost_usd`) is updated for Bedrock/Vertex regional pricing differences: not documented; `provider` field exists but no per-provider price table is mentioned.

## Q2. What does Codex CLI `exec --json` emit, and is there any USD figure or rate-limit info under ChatGPT-subscription auth vs API key?

### Takeaway
`codex exec --json` emits `turn.completed` with `usage: {input_tokens, cached_input_tokens, output_tokens}` — tokens only, no USD, no rate-limit fields. Rate-limit state (5-hour and weekly window `used_percent`, `resets_in_seconds`) is written to the local session rollout files (`~/.codex/sessions/.../rollout-*.jsonl`, `token_count` events) and shown by `/status`; ChatGPT-plan pricing is denominated in "credits per 1M tokens", API-key usage in USD per token.

### Cited Findings
- `codex exec --json` / `--experimental-json`: "Print newline-delimited JSON events instead of formatted text." Also `--output-last-message` / `-o`, `--output-schema`, `-c/--config` inline TOML overrides, `--ephemeral` ("Run without persisting session rollout files to disk"), `codex exec resume --last`, `codex exec fork <SESSION_ID>`. No usage, cost or rate-limit fields documented on the official command page. — [Codex developer commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
- Event types (JSONL): `thread.started` (carries `thread_id`), `turn.started`, `item.started`, `item.updated`, `item.completed`, `turn.completed` ("carries `usage`"), `turn.failed`, plus a fatal error event. Item types: `agent_message`, `command_execution`, `reasoning`, `file_change`, `mcp_tool_call`, `web_search`, `plan_update`. Verbatim sample: `{"type":"turn.completed","usage":{"input_tokens":24763,"cached_input_tokens":24448,"output_tokens":122}}`. "There is no `rate_limits` field and no cost or USD field in the documented schema." Pre-v0.44.0 schema renamed `item_type`→`type`, `assistant_message`→`agent_message`; "the stream has no schema version indicator." **[secondary]** — [codex exec JSONL reference (Daniel Vaughan)](https://codex.danielvaughan.com/2026/04/08/codex-exec-jsonl-reference/)
- Session rollout files: `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`, records with `type: "event_msg"`, `payload.type: "token_count"`, `payload.info.total_token_usage` and `payload.info.last_token_usage` each `{input_tokens, cached_input_tokens, output_tokens, reasoning_output_tokens, total_tokens}`, and `payload.rate_limits.primary` / `.secondary` each `{used_percent, window_minutes, resets_in_seconds}` (primary ≈ 5h, `window_minutes: 299`; secondary ≈ weekly, `window_minutes: 10079`). **[secondary]** — [codex-ratelimit README](https://github.com/xiangz19/codex-ratelimit)
- Other third-party tools report the same windows via response headers `x-codex-primary-used-percent`, `x-codex-primary-window-minutes`, `x-codex-primary-reset-at` (+ secondary). **[secondary, unstable]** — [search summary](https://www.mintlify.com/ndycode/codex-multi-auth/concepts/quota-management)
- Config keys relevant to spend: `features.rollout_budget` (experimental, off by default) with `enabled`, `limit_tokens` (required when enabled), `reminder_interval_tokens` (default 10% of limit), `sampling_token_weight`, `prefill_token_weight` — a *token* budget per rollout; `tool_output_token_limit`; `model_auto_compact_token_limit`; `memories.min_rate_limit_remaining_percent` (default 25) gates memory generation on remaining rate-limit window; "No cost or pricing keys appear." — [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- Auth selection: `forced_login_method = "chatgpt" | "api"`, `forced_chatgpt_workspace_id`, `cli_auth_credentials_store = file|keyring|auto|ephemeral`; `openai_base_url` overrides the built-in `openai` provider's base URL ("Project-local `.codex/config.toml` ignores it"); `chatgpt_base_url` overrides the login-flow URL. — [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- OTel: `otel.exporter = none|otlp-http|otlp-grpc`, `otel.metrics_exporter = none|statsig|otlp-http|otlp-grpc` (default `statsig`), `otel.trace_exporter`, `otel.environment`, `otel.log_user_prompt`; `analytics.enabled=false` "also disables custom OTLP metrics exporters"; `otel` ignored in project-local config. `history.persistence = save-all|none`. `notify = ["cmd", ...]` receives a JSON payload. — [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- Pricing under ChatGPT sign-in: plans Plus $20, Pro $100/$200/$500, Business $20–25/user; "Pro currently has no five-hour limit"; "Weekly limits may also apply"; token rates are listed in **credits per 1M tokens** (e.g. GPT-6 Astra 250 in / 25 cached / 1,250 out; GPT-6.1 Sol 50 / 2.5 / 250; GPT-6 Luna 2.5 / 0.25 / 12.5), "Codex credit billing has no separate cache-write charge"; "A typical GPT-5.6 Sol task may use 2-15 credits"; Fast mode 2.5× included / 2× credits; API-key usage "based on API pricing"; "In an active Codex CLI session, run `/status` to see remaining limits"; dashboard at chatgpt.com/codex/settings/usage. — [Codex pricing](https://learn.chatgpt.com/docs/pricing)
- Under ChatGPT auth, usage "draws from the same pool" across CLI, IDE, and cloud tasks; two windows (rolling 5-hour and weekly). **[secondary]** — [inventivehq](https://inventivehq.com/blog/codex-cli-usage-rate-limits)

### Inferences
- For Codex nodes the only harness-native per-run number is tokens (`turn.completed.usage`); an orchestrator must price them itself (USD table for API key; credits table for ChatGPT plans) or skip pricing.
- `reasoning_output_tokens` appears in the session file's `token_count` but not in the `exec --json` `usage` object; output_tokens in the stream presumably already includes reasoning **[uncertain]**.
- Because `--ephemeral` disables rollout files, an orchestrator that wants `rate_limits` must *not* use `--ephemeral` and must parse `~/.codex/sessions` (or set `CODEX_HOME` per node) — a fragile, undocumented interface.
- `features.rollout_budget.limit_tokens` is the closest Codex analogue to `--max-budget-usd`, but it is in tokens, experimental, and the docs do not say what happens when it is hit (reminders are mentioned; hard stop is **[uncertain]**).

### Gaps
- No official OpenAI doc for the `exec --json` event schema was found (the official page only says "newline-delimited JSON events"); the schema above is from a third-party reference.
- No official doc for `token_count`/`rate_limits` in session files or for `x-codex-*` headers.
- Whether `codex exec --json` ever emits a rate-limit event (newer versions may; the app-server protocol reportedly has one) — unverified.
- No documented way to pass OpenAI `user` / `metadata` fields per request from Codex (see Q3).

## Q3. What do the Anthropic Admin Usage & Cost API and the OpenAI Usage/Costs API provide for reconciliation, and can an orchestrator tag requests to attribute cost to a pipeline run?

### Takeaway
Both vendors offer org-level, bucketed (1m/1h/1d) token usage and daily USD cost reports grouped by API key / workspace / project / user / model — but neither supports arbitrary per-request tags, and neither Claude Code nor Codex exposes a knob to set the Messages-API `metadata.user_id` or OpenAI `user`/`metadata` fields. Attribution to a pipeline run therefore has to be done by **credential identity** (one key per run/pipeline/team) or at a gateway using headers Claude Code already sends (`x-claude-code-session-id`, `x-claude-code-agent-id`, `ANTHROPIC_CUSTOM_HEADERS`).

### Cited Findings

**Anthropic Usage & Cost Admin API**
- Usage: `GET /v1/organizations/usage_report/messages` with `starting_at`, `ending_at`, `bucket_width` ∈ `1m` (default 60 buckets, max 1,440), `1h` (24 / 168), `1d` (7 / 31); filters `api_key_ids[]`, `workspace_ids[]`, `models[]`, `service_tiers[]`, `context_window[]`, `inference_geos[]`, `speeds[]`; `group_by[]` over the same dimensions. Tracks "uncached input, cached input, cache creation, and output tokens" and server tool usage. — [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)
- Cost: `GET /v1/organizations/cost_report` — "All costs in USD, reported as decimal strings in lowest units (cents)"; "Group costs by workspace or description"; "Daily granularity only (`1d`)"; Priority Tier costs excluded. — [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)
- Freshness/polling: "Usage and cost data typically appears within 5 minutes of API request completion"; "The API supports polling once per minute for sustained use." — [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)
- Auth: Admin API key (`sk-ant-admin01-...`), `org:admin` OAuth token, or a non-workspace-scoped key; "The Admin API is unavailable for individual accounts"; not available on Claude Platform on AWS. Claude Enterprise (claude.ai) orgs use a separate Enterprise Analytics API with an Analytics API key instead. — [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)
- Per-user Claude Code cost: "Use the Claude Code Analytics API, which provides per-user estimated costs … without the performance limitations of breaking down costs by many API keys. For general API usage with many keys, use the Usage API to track token consumption as a cost proxy." — [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)
- Console-authenticated Claude Code lands in an auto-created workspace named "Claude Code": "You cannot create API keys for this workspace; it is exclusively for Claude Code authentication and usage." Workspace spend limits and workspace rate limits can be set on it. — [Manage costs](https://code.claude.com/docs/en/costs)
- No `metadata`/`user_id`/tag grouping dimension is documented for either endpoint. — [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)

**OpenAI Usage & Costs API**
- `GET /v1/organization/usage/completions`: `start_time` (required, Unix seconds), `end_time`, `bucket_width` ∈ `1m`/`1h`/`1d` (default `1d`), filters `project_ids`, `user_ids`, `api_key_ids`, `models`, `batch`, `group_by` (e.g. `["model","project_id"]`; `user_id`, `api_key_id`, `batch` also usable), `limit`, `page`/`next_page`. Result fields: `input_tokens`, `output_tokens`, `input_cached_tokens`, `input_audio_tokens`, `output_audio_tokens`, `num_model_requests`, `project_id`, `user_id`, `api_key_id`, `model`, `batch`. — [OpenAI cookbook: Usage API](https://developers.openai.com/cookbook/examples/completions_usage_api)

Admin key (Bearer) required. — [OpenAI cookbook](https://developers.openai.com/cookbook/examples/completions_usage_api); [API reference listing](https://developers.openai.com/api/reference/resources/organization/subresources/audit_logs/methods/get_costs)

- No data-latency statement found for the OpenAI endpoints (official reference page returned 403 to fetch).

**Tagging / attribution hooks the harnesses actually expose**
- Claude Code request headers a gateway can consume: `x-claude-code-session-id` ("Use it to aggregate all requests from one session without parsing request bodies"), `x-claude-code-agent-id`, `x-claude-code-parent-agent-id` ("Use it with the session ID to attribute cost to parallel agents"); plus "If your developers set `ANTHROPIC_CUSTOM_HEADERS`, those headers appear on requests as well." - `ANTHROPIC_CUSTOM_HEADERS` format: "one `Name: Value` pair per line" (`export ANTHROPIC_CUSTOM_HEADERS="X-Org-Route: prod"`); in settings `env` use `\n` between pairs; such headers "count as headers that need approval" when they come from project settings. — [Connect to an LLM gateway](https://code.claude.com/docs/en/llm-gateway-connect)
- The gateway guide documents request *headers* and body fields to forward; it does not mention a `metadata.user_id` body field being set by Claude Code. Claude Code also prepends a "system prompt attribution block" (client version + conversation fingerprint) read by Anthropic for attribution; `CLAUDE_CODE_ATTRIBUTION_HEADER=0` omits it. — [Gateway compatibility guide](https://code.claude.com/docs/en/llm-gateway-protocol)
- Codex: `model_providers.<id>.http_headers` (static) and `env_http_headers` (from env vars) add headers to every request; `wire_api = "responses"` is the "Only supported value" (so a gateway must speak the Responses API). — [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- `--session-id <uuid>` lets an orchestrator choose Claude Code's session id up front (and hence the `x-claude-code-session-id` header value and the OTel `session.id`). — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` turns off version checks/telemetry outside the gateway path; Claude Code "attaches a credential to a telemetry or usage-metrics request only when the request goes to the host the credential belongs to." — [Connect to an LLM gateway](https://code.claude.com/docs/en/llm-gateway-connect)

### Inferences
- The cheapest robust attribution for API-key nodes is **one API key (Anthropic) / one project+key (OpenAI) per pipeline or per tenant**, then reconcile with the vendor Usage API grouped by `api_key_id`/`project_id`. Per-*run* keys are impractical (Anthropic explicitly warns about "performance limitations of breaking down costs by many API keys").
- Per-run attribution with vendor reconciliation at run granularity is not achievable without a gateway; with a gateway it is trivial for Claude Code (session-id header) and feasible for Codex (static `http_headers` per node, e.g. `X-Run-Id`).
- Vendor cost APIs give daily USD; usage APIs give 1-minute tokens. Any "USD per node" figure at sub-day granularity is necessarily an estimate (tokens × price).

- No documentation found on whether Claude Code populates Messages-API `metadata.user_id`, or on any env var to set it. **[uncertain]**
- No documentation found on Codex setting OpenAI `user`/`metadata`/`prompt_cache_key` per request.

## Q4. How do LLM gateways (LiteLLM, Portkey, Helicone, Cloudflare AI Gateway, Anthropic's Claude apps gateway) meter cost per key/tag/team and enforce budgets, and can Claude Code / Codex be pointed at them?

### Takeaway
All four gateways price requests from token counts with their own price tables and attribute by credential plus request headers; only LiteLLM and Portkey enforce *budgets* (LiteLLM: per key/team/user/customer with `max_budget` + `budget_duration`, reservation-based; Portkey: per provider/workspace cost or token caps with weekly/monthly reset). Claude Code is pointed at any Anthropic-format gateway with `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY` (+ `ANTHROPIC_CUSTOM_HEADERS`); Codex via `model_providers.<id>.base_url` (Responses API only) or `openai_base_url`.

### Cited Findings

**Pointing the harnesses at a gateway**
- Claude Code: `ANTHROPIC_BASE_URL=https://llm-gateway.example.com` plus `ANTHROPIC_AUTH_TOKEN` (→ `Authorization: Bearer`) or `ANTHROPIC_API_KEY` (→ `x-api-key`) or `apiKeyHelper` (sent in both; cached 5 min, `CLAUDE_CODE_API_KEY_HELPER_TTL_MS`). - A gateway is the only place where *enforcement* and *attribution* for subscription-free, API-billed nodes can be done without trusting the harness's self-report — but it converts every node to per-token API billing (subscription windows no longer apply), which may be the opposite of what a subscription-heavy user wants.

- For Codex, gateway attribution relies on static `http_headers` in a per-node `config.toml` (or `-c model_providers.x.http_headers.X-Run-Id=...` overrides) because Codex has no session-id header equivalent documented.

## Q5. What unit do existing orchestrators use (USD, tokens, turns, session-hours, credits)? Which worked and which were criticised?

### Takeaway
Every shipping orchestrator that enforces anything enforces in a **money-denominated estimate** (USD cents, "AI Credits" at $0.01, or Anthropic "list cost"), computed client-side or by the vendor from tokens; none enforces in raw tokens except Codex's experimental `rollout_budget`. Turn and wall-clock caps are always present as a second safety net. Common criticisms: estimates diverge from invoices, caps are per-run/per-session not global, subscription spend is unmeasurable and gets amortised.

### Cited Findings

**Paperclip** (USD cents, monthly)
- Budgets: three scopes — organization (monthly), agent (monthly), project (lifetime); "Monthly budgets reset on the 1st of each UTC month"; amounts entered in dollars; API field `budgetMonthlyCents` (e.g. `200000` = $2,000/month) **[secondary for field name]**. Enforcement: 80% → warning recorded ("doesn't pause the agent"); 100% → "The agent is auto-paused and sends no heartbeats … resumes when the budget is raised or the month rolls over." Task-level budgets not enforced in V1. — [Paperclip costs](https://docs.paperclip.ing/guides/day-to-day/costs); [search summary of costs-and-budgets](https://docs.paperclip.ing/guides/board-operator/costs-and-budgets)
- Measurement: each heartbeat "records the agent, model, token counts (input, output, and cached input), and dollar cost"; "Costs are cache-adjusted … what the provider actually billed after the cache discount"; "When an adapter reports only a single cost figure, Paperclip treats that figure as the billed amount"; per-model rows labelled `provider / model / billingType` with run types `api` or `subscription`. — [Paperclip costs](https://docs.paperclip.ing/guides/day-to-day/costs)
- Subscription handling: subscription fees go to a separate finance ledger; "subscription-day debits are estimates … typically derived from the plan price divided by the billing cycle length" until an invoice is imported; quota bars per provider show window label, consumption, reset time and data source ("provider API, estimated, or last-known cached value"). — [Paperclip costs](https://docs.paperclip.ing/guides/day-to-day/costs)
- Known issues: "Warning card bug in v2026.1012.0 — the 80% warning card still uses hard-stop wording"; costs attributed to a project only when the run came from a project-linked issue, otherwise "Unattributed". — [Paperclip costs](https://docs.paperclip.ing/guides/day-to-day/costs)

**gh-aw (GitHub Agentic Workflows)** (AI Credits, 1 AIC = $0.01)
- "AIC is the general metric GitHub Agentic Workflows use for monitoring and budgeting across engines, and 1 AIC equals $0.01 USD." Frontmatter `max-ai-credits`: "enabled by default and defaults to `1000` (`1k`) when omitted"; negative value disables; `max-daily-ai-credits` (24-hour cap per workflow, off by default); `max-turns` "Defaults to `500`"; `timeout-minutes` (fallback 20 min for the agentic step); `max-turn-cache-misses` default 5. — [gh-aw frontmatter](https://github.github.com/gh-aw/reference/frontmatter/); [GitHub docs](https://docs.github.com/en/copilot/concepts/agents/about-github-agentic-workflows)
- Billing: Copilot engine → "AIC usage maps to AI credits in GitHub Copilot billing"; "Claude, Codex, and Gemini inference is billed directly by Anthropic, OpenAI, and Google … through your provider account." Detection of cap: a `403` from the local API proxy may indicate `max-ai-credits` enforcement; "gh-aw compares the proxy's token-usage total with the configured cap." Inspect with `gh aw logs <workflow> --last 5 --json` (`aic`, `action_minutes`, `per_run_breakdown`) and `gh aw audit <run-id>`. — [gh-aw billing](https://github.github.com/gh-aw/reference/billing/)
- Caveat: "AIC values are best-effort estimates and may not exactly match provider invoices." Effective Tokens (ET) were replaced by AI Credits in June 2026 (ET kept as a legacy field). — [GitHub docs](https://docs.github.com/en/copilot/concepts/agents/about-github-agentic-workflows); [gh-aw blog](https://github.github.com/gh-aw/blog/2026-06-08-migrating-from-effective-tokens-to-ai-credits/)
- Related: Copilot CLI `--max-ai-credits` is "a soft cap. Because usage is only known after a response returns, the final usage may slightly exceed the limit." — [GitHub changelog](https://github.blog/changelog/2026-07-01-set-ai-credit-session-limits-in-copilot-cli-and-sdk/)

**Gas City** (no budget unit)
- Gas City (Steve Yegge; v1.0.0 2026-04-24, v1.2.1 2026-06-01) is an SDK for building orchestrators on Beads + Dolt; the reviewed material has "no budget, cost-accounting, token-limit, or spend-control features"; cost is "inherited, not solved": "Token and subscription spend scales with worker count"; "hundreds of concurrent workers mean hundreds of concurrent token meters"; agent CLIs "$20-200+/mo each" with accounts "per concurrent worker". **[secondary]** — [rywalker.com review](https://rywalker.com/research/gas-city); [The New Stack on Gas Town](https://thenewstack.io/steve-yegges-ai-agent-orchestration-project-gas-town-comes-to-the-cloud-and-brings-the-wasteland-with-it/)

**Claude Code Routines** (subscription usage + hourly run caps)
- "Routines draw down subscription usage the same way interactive sessions do." Hourly limits: scheduled runs 100/hour per account; Run now/API fires 30/hour per routine; API fires 100/hour per account; "None of these hourly limits has overage." Over the subscription limit: "organizations with usage credits turned on can keep running routines on metered overage. Without usage credits, additional runs are rejected until your usage window resets." Routines belong to the individual claude.ai account. — [Routines](https://code.claude.com/docs/en/routines)
- Third-party guides claim API-billed routines pay "$0.08 per session-hour" plus tokens. **[secondary, unconfirmed in official routine docs]** — [tokencost.app](https://tokencost.app/blog/claude-code-routines-pricing)

**Anthropic Managed Agents** (list-price USD per session + $0.08/session-hour)
- Pricing: tokens at Messages list rates (caching multipliers apply, no Batch discount), web search $10/1,000, `inference_geo: "us"` → 1.1×, "Session runtime $0.08 per session-hour, metering `running` status duration"; "Runtime is measured to the millisecond and accrues only while the session's status is `running`"; idle/rescheduling/terminated don't count. Worked example: 1-hour Opus 5.5 session, 50k in / 15k out = $0.58; with 40k cache reads = $0.428. — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Budget: `budget={"type": "limit", "max_list_cost": {"currency": "USD", "amount": "10"}}` on `sessions.create` (beta `managed-agents-2026-04-01`, SDK `anthropic>=0.121.0`); `amount` is "an integer string in the currency's minor units"; measured as "model token cost at public list price, summed across every thread in the session, including subagent threads"; "List price applies regardless of any negotiated discount"; models without a public list price fail create with `model_not_budgetable`; stop reason `budget_reached` (a pause, not a failure); "enforced between model requests, so the recorded `list_cost` can land slightly past `max_list_cost`" (example: $0.10 cap stopped at $0.12); raising the cap resumes automatically; "A budget can only be attached at creation"; "It bounds one run, not an org, a workspace, or a day of traffic"; webhook `session.budget_reached`; `session.usage` event carries `usage.list_cost`, `budget.max_list_cost`, token counts, `active_seconds`. The cookbook only describes token cost as counted toward the cap (session-hours not mentioned). — [Cookbook: cap session spend](https://platform.claude.com/cookbook/managed-agents-cma-cap-session-spend)
- Criticism: "A deployment with a $5 budget running two hundred sessions can spend $1,000." **[secondary]** — [search summary](https://www.finout.io/blog/anthropic-just-launched-managed-agents.-lets-talk-about-how-were-going-to-pay-for-this)

**Codex** (tokens, experimental)
- `features.rollout_budget` with `limit_tokens` is a per-rollout token budget with reminders every `reminder_interval_tokens`. — [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)

**Claude Code itself** (USD estimate + turns)
- `--max-budget-usd` (estimate) and `--max-turns` as described in Q1. Agent-team guidance notes "Agent teams use approximately 7x more tokens than standard sessions when teammates run in plan mode." Enterprise average "around $13 per developer per active day and $150-250 per developer per month, with costs remaining below $30 per active day for 90% of users." — [Manage costs](https://code.claude.com/docs/en/costs)

### Inferences
- Convergence: GitHub (AIC = cents), Paperclip (cents), Anthropic Managed Agents (cents, list price), Claude Code (`total_cost_usd`, `cost_usd_micros`) all chose a **money unit at list price**, computed from tokens, with explicit "estimate, not invoice" disclaimers. This is the de-facto industry unit.
- All of them pair the money cap with structural caps (turns, wall-clock, daily cap), and treat the money cap as soft (overshoot by one response is normal).
- Nobody has solved subscription accounting; Paperclip's "plan price ÷ billing-cycle days" amortisation plus provider quota bars is the only concrete attempt found.

### Gaps
- Gas City official docs (docs.gascityhall.com) were not fetched; a budget feature could exist there.
- No systematic user criticism of Paperclip/gh-aw accounting accuracy found beyond vendor-admitted caveats.

## Q6. The 2–3 most practical accounting/enforcement designs for the framework

### Takeaway
Given the evidence, the simplest robust design is **"tokens are the ledger, list-price USD is the derived unit, harness-reported USD is used when it carries a trusted `costBasis`, and enforcement is a soft USD-estimate cap backed by hard turn/wall-clock caps"** — with per-node `billing_class` (`subscription` | `api` | `gateway` | `managed_agents`) recorded so that USD on subscription nodes is understood as consumption-equivalent, not spend.

### Design A — Token ledger + pluggable price table → USD estimate (recommended core)
Data sources per node:
- Claude Code: `result.modelUsage[model].{inputTokens, outputTokens, cacheReadInputTokens, cacheCreationInputTokens, webSearchRequests, costUSD, costBasis, provider, canonicalModel}` from `claude -p --output-format json` (covers subagents; `usage` does not). — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking); [TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Codex: `turn.completed.usage.{input_tokens, cached_input_tokens, output_tokens}` from `codex exec --json`. **[secondary schema]** — [JSONL reference](https://codex.danielvaughan.com/2026/04/08/codex-exec-jsonl-reference/)
- Price table: Anthropic list table (e.g. Opus 5.5 $4/$20 per MTok, cache write 5m $5 / 1h $8, cache read $0.20; Sonnet 5.5 $2/$10) — [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing); OpenAI API pricing for API-key nodes; OpenAI *credits* table for ChatGPT-plan nodes (e.g. GPT-6.1 Sol 50/2.5/250 credits per MTok) — [Codex pricing](https://learn.chatgpt.com/docs/pricing). Allow a `multiplier`/`overrides` layer mirroring Claude Code's `modelPricing` shape so one config can feed both the orchestrator and Claude Code managed settings. — [Settings reference](https://code.claude.com/docs/en/settings-reference)
- Enforcement: pass `--max-budget-usd` (Claude Code) derived from the node's remaining budget; for Codex, the orchestrator must itself watch cumulative tokens across turns (no USD cap in Codex; optional `features.rollout_budget.limit_tokens`). Always add `--max-turns` / Codex turn count and a wall-clock timeout (gh-aw default: 500 turns, 20 min). — [CLI reference](https://code.claude.com/docs/en/cli-reference); [gh-aw frontmatter](https://github.github.com/gh-aw/reference/frontmatter/)
Pros: works identically for subscription, API, gateway, Bedrock/Vertex; one unit (USD-equivalent) in UI; reconcilable later against Usage/Cost APIs grouped by `api_key_id`/`project_id`; matches what gh-aw, Paperclip, Managed Agents do.
Cons: price table maintenance (new models → `costBasis: unknown`); cannot model contracted rates, priority tier, batch; Codex ChatGPT-plan nodes must be priced in credits or "notional USD"; cache-TTL differences (1h on subscription, 5m on API) mean identical token counts have different real cost. — [Manage costs](https://code.claude.com/docs/en/costs)

### Design B — Harness-reported cost when trustworthy, else tokens × table (Design A with a precedence rule)
- Rule: if `costBasis ∈ {list, managed}` use `modelUsage[*].costUSD` / `total_cost_usd` directly (Claude Code already applies 1.1× geo and `modelPricing`); if `costBasis == unknown` or the harness is Codex, fall back to Design A pricing; if the node ran under a gateway, prefer the gateway's spend record (LiteLLM `/key/info` `spend`, Portkey Analytics, Helicone properties, Cloudflare logs with `cf-aig-custom-cost`). For Managed Agents nodes, read `session.usage.list_cost` and `active_seconds` and add `$0.08 × active_seconds/3600`. — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking); [LiteLLM budgets](https://docs.litellm.ai/docs/proxy/users); [Cookbook](https://platform.claude.com/cookbook/managed-agents-cma-cap-session-spend); [Pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- This is essentially Paperclip's rule ("When an adapter reports only a single cost figure, Paperclip treats that figure as the billed amount"). — [Paperclip costs](https://docs.paperclip.ing/guides/day-to-day/costs)
Pros: least code when harness numbers are good; stays correct as Anthropic updates its bundled table with each Claude Code release; `modelPricing` lets enterprises get contracted-rate numbers for free.
Cons: two code paths; numbers from different sources are not comparable (list vs managed vs gateway-actual); crash results can be zeroed (must fall back to summing assistant-message usage, which loses output tokens and subagents). — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

### Design C — Limits in turns + wall-clock (+ optional token ceiling); cost is observability only
- Enforce only `--max-turns`, timeouts, and (optionally) a raw token ceiling computed from `modelUsage`/`turn.completed`; report USD estimates and, for subscription nodes, remaining-window percentages (Codex: `rate_limits.primary/secondary.used_percent` from session files **[secondary]**; Claude Code: only via `/usage` or a gateway reading `anthropic-ratelimit-unified-*` — no headless hook found). — [codex-ratelimit](https://github.com/xiangz19/codex-ratelimit); [Gateway compatibility guide](https://code.claude.com/docs/en/llm-gateway-protocol)
- Push real cost control to where billing actually happens: vendor workspace/project spend limits (Anthropic "Claude Code" workspace spend limit, OpenAI project budgets), gateway budgets (LiteLLM `max_budget`/`budget_duration`, Portkey cost limits), or Managed Agents `budget`. Reconcile daily with the Cost APIs (5-minute freshness on Anthropic; daily buckets). — [Manage costs](https://code.claude.com/docs/en/costs); [Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)
Pros: zero price-table maintenance; honest for subscription nodes (where USD is meaningless and the window is the real constraint); turn/wall-clock caps are what every existing orchestrator already relies on as the hard stop.
Cons: no per-node dollar guard for API-key nodes unless a gateway/workspace limit exists (and workspace limits are coarse); a runaway node with few turns but huge context (compaction, long context) can burn a lot before a turn cap bites; no shared unit across heterogeneous nodes for UI.

### Cross-cutting implementation notes (all designs)
- Record per node: `harness`, `authMethod` (from `claude auth status` → `claude.ai|oauth_token|api_key|api_key_helper|third_party`; Codex `forced_login_method` or auth file), `billing_class`, `provider` (from `modelUsage.provider`), `price_basis` (`harness-list|harness-managed|table|gateway|vendor-report|none`). — [CLI reference](https://code.claude.com/docs/en/cli-reference); [TS reference](https://code.claude.com/docs/en/agent-sdk/typescript)
- Give each node its own Claude Code session (`--session-id <uuid>`, no `--resume`) so `total_cost_usd` is per-node, or if resuming, read only the final result (v2.1.277+ restores totals). — [Track cost and usage](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Treat every USD cap as soft; follow Claude Code's "leave headroom" and Managed Agents' "enforced between model requests" semantics; expect overshoot of one response. — [CLI reference](https://code.claude.com/docs/en/cli-reference); [Cookbook](https://platform.claude.com/cookbook/managed-agents-cma-cap-session-spend)
- For attribution to a pipeline run at the vendor/gateway layer: set `ANTHROPIC_CUSTOM_HEADERS="X-Pipeline-Run: <id>"` and `--session-id`; set Codex `model_providers.<id>.http_headers` per node; enable `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` when behind a custom base URL to get `x-claude-code-request-class`/`prompt-id`. — [Connect to a gateway](https://code.claude.com/docs/en/llm-gateway-connect); [Gateway compatibility guide](https://code.claude.com/docs/en/llm-gateway-protocol); [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- OTel as the parallel real-time stream: `OTEL_RESOURCE_ATTRIBUTES="pipeline=<name>,run_id=<id>,node=<id>"` on each spawned Claude Code process gives `claude_code.cost.usage`/`token.usage` series per node with no parsing of stdout; remember OTel env is not propagated to Bash/hook subprocesses. — [Monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Subscription nodes: present USD as "list-price equivalent"; surface window state where available; consider Paperclip-style plan-price amortisation only as a reporting convenience, never for enforcement. — [Paperclip costs](https://docs.paperclip.ing/guides/day-to-day/costs)
