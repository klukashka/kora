# Coding agents as headless pipeline steps: interfaces, config surfaces, orchestrators, artifacts, runtimes (as of 2026-10-14)

Scope note: all facts below come from pages fetched on 2026-10-14. Official docs for Claude Code moved to `code.claude.com/docs`, Agent SDK docs to `code.claude.com/docs/en/agent-sdk/*`, Managed Agents to `platform.claude.com/docs/en/managed-agents/*`, and OpenAI Codex docs now redirect from `developers.openai.com/codex/*` to `learn.chatgpt.com/docs/*`. ## KQ1. For each agent: exact CLI/SDK surface for non-interactive runs, session resume, budget limits, structured output, config files (paths/formats)

### Takeaway
Every major coding agent now has a "print/exec" mode that emits newline-delimited JSON events plus a final result object; Claude Code (`claude -p … --output-format json|stream-json`, `--json-schema`, `--max-budget-usd`, `--resume`) and Codex (`codex exec --json --output-schema -o`, `codex exec resume`) are the most complete, while OpenCode (`opencode run --format json` + HTTP server), Pi (`--mode json|rpc`), Gemini CLI (`-p --output-format stream-json`), Amp (`-x --stream-json`) and the hosted APIs (Cursor Cloud Agents v1, Devin v3, Jules v1alpha, Claude Managed Agents) each expose a narrower but scriptable surface. Only Claude Code and Managed Agents expose a hard dollar budget as a first-class run parameter.

### Cited Findings

#### Claude Code CLI (`claude -p`)
- Non-interactive mode is `claude -p "query"` / `--print`; it is described as "Query via SDK, then exit"; `cat file | claude -p "query"` pipes stdin; `claude -c -p` continues the most recent conversation; `claude -r "<session>" "query"` resumes by ID or name — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- `--output-format` accepts `text`, `json`, `stream-json`; `--input-format` accepts `text`, `stream-json`; `--include-partial-messages` and `--replay-user-messages` require stream-json — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- `--json-schema '{…}'`: "Get validated JSON output matching a JSON Schema after the agent completes its workflow (print mode only)"; result lands in the `structured_output` field; invalid schemas exit with `Error: --json-schema is not a valid JSON Schema`; `format` keyword is accepted but not enforced — [Headless docs](https://code.claude.com/docs/en/headless)
- `--max-budget-usd 5.00`: "Stop the run once estimated spend on API calls reaches this amount (print mode only)… Spend from subagents counts toward the cap. Spend can pass the cap, so leave headroom… Once spend reaches the cap, spawning another subagent fails with `Budget limit reached`" (cap-enforcement behaviors need v2.1.217+) — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- `--max-turns 3`: "Limit the number of agentic turns (print mode only). Exits with an error when the limit is reached. No limit by default." — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- Session control: `--resume/-r <id|name|/abs/path.jsonl>`, `--continue/-c`, `--fork-session`, `--session-id <uuid>`, `--name/-n`, `--no-session-persistence` (print mode only) — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- `session_id=$(claude -p "Start a review" --output-format json | jq -r '.session_id'); claude -p "Continue that review" --resume "$session_id"` — the two commands can run from different directories since v2.1.223 ID search covers every project on the machine — [Headless docs](https://code.claude.com/docs/en/headless)
- Permissions in print mode: `--allowedTools "Bash(git diff *),Read"`, `--disallowedTools`, `--tools "Bash,Edit,Read"` (restrict built-ins; `""` disables all), `--permission-mode default|acceptEdits|plan|auto|dontAsk|bypassPermissions`, `--dangerously-skip-permissions`, `--permission-prompt-tool <mcp_tool>`, and `--permission-prompts none` (v2.1.259+) which denies anything that would prompt and removes `AskUserQuestion` — [CLI reference](https://code.claude.com/docs/en/cli-reference); [Headless docs](https://code.claude.com/docs/en/headless)
- `--bare` skips auto-discovery of hooks, skills, commands, subagents, plugins, MCP servers, auto memory, and CLAUDE.md; "never reads OAuth credentials or the system keychain" so needs `ANTHROPIC_API_KEY`; "`--bare` is the recommended mode for scripted and SDK calls, and will become the default for `-p` in a future release" — [Headless docs](https://code.claude.com/docs/en/headless)
- Without `--bare`, "a `-p` session runs the hooks in a project's `.claude/settings.json` and connects the servers in its `.mcp.json`, even in a folder you've never trusted. A `-p` session shows no workspace trust dialog" — [Headless docs](https://code.claude.com/docs/en/headless)
- System prompt flags: `--system-prompt`, `--system-prompt-file` (replace), `--append-system-prompt`, `--append-system-prompt-file` (append), `--system-prompt-snapshot off`; `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` line splits cached static part from per-run context (v2.1.275+); `--exclude-dynamic-system-prompt-sections` improves cache reuse for multi-user scripted workloads — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- Other automation flags: `--agents '<json>'` (or path to JSON file with `-p`, v2.1.281+), `--agent <name>`, `--mcp-config ./mcp.json`, `--strict-mcp-config`, `--settings <file|json>`, `--setting-sources user,project,local`, `--model`, `--fallback-model sonnet,haiku`, `--effort low|medium|high|xhigh|max|ultracode`, `--worktree/-w <name>`, `--add-dir`, `--plugin-dir`, `--betas`, `--init`/`--maintenance` (run Setup hooks, print mode only), `--restricted` (v2.1.248+, for eval harnesses on shared machines) — [CLI reference](https://code.claude.com/docs/en/cli-reference)
- Exit codes: 0 on success, non-zero on failure; SIGTERM exits 143 and runs `SessionEnd` hooks; piped stdin capped at 10 MB; a `-p` run may stay open up to 10 min waiting for background subagents/commands (`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`) — [Headless docs](https://code.claude.com/docs/en/headless)
- stream-json extras: `system/init` carries `model`, `tools`, `mcp_servers[{name,status}]`, `mcp_server_errors`, `plugins`, `plugin_errors`, `capabilities`; `system/api_retry` events carry `attempt`, `max_retries`, `retry_delay_ms`, `error_status`, `error` category; `--include-hook-events` adds `hook_started/hook_progress/hook_response`; `--forward-subagent-text` (v2.1.211+) emits subagent messages with `parent_tool_use_id` — [Headless docs](https://code.claude.com/docs/en/headless)
- `claude -p` also has a cloud form: `claude -p "message" --cloud <session_id>` queues a message into an existing cloud session and exits; `--output-format json` returns `{ok, session_id, url}` — [Claude Code in the cloud](https://code.claude.com/docs/en/claude-code-on-the-web)
- Background sessions: `claude --bg "task"` (cannot combine with `-p`), `claude agents --json --all` prints a JSON array with `cwd`, `kind`, `startedAt`, `id`, `state` (`working|blocked|done|failed|stopped`), `status` (`busy|waiting|idle`), `waitingFor`, `sessionId`, `name`; supervisor state in `~/.claude/daemon/roster.json` and `~/.claude/jobs/<id>/state.json`; research preview — [Agent view](https://code.claude.com/docs/en/agent-view)

#### Claude Code settings.json / hooks / subagents / skills / plugins / MCP (config surface)
- Settings scopes: user `~/.claude/settings.json`; shared project `.claude/settings.json`; project local `.claude/settings.local.json`; managed `managed-settings.json` (e.g. `/etc/claude-code/managed-settings.json` on Linux), MDM, or server-managed settings from the claude.ai console. Precedence highest→lowest: managed, `--settings` CLI, project local, shared project, user; lists (e.g. `permissions.allow`) merge across scopes — [Settings](https://code.claude.com/docs/en/settings); [Dev containers](https://code.claude.com/docs/en/devcontainer)
- `~/.claude.json` is a separate global file holding sign-in session, MCP server configs, per-project trust; `CLAUDE_CONFIG_DIR` relocates all of `~/.claude` — [Settings](https://code.claude.com/docs/en/settings)
- `permissions.defaultMode` values `auto` and `bypassPermissions` "don't take effect from project or local settings"; `permissions.allow` rules and most `env` values apply only after the folder is trusted — [Settings](https://code.claude.com/docs/en/settings)
- Hooks config shape: `{"hooks": {"PreToolUse": [{"matcher": "Bash", "hooks": [{"type": "command", "command": "…", "if": "Bash(rm *)"}]}]}}`; handler types `command`, `http` (POSTs input JSON to `url`), `mcp_tool`, `prompt`, `agent`; common fields `type`, `if`, `timeout`, `statusMessage`, `once`; default timeouts 600 s (command/http/mcp_tool), 30 s (prompt), 60 s (agent) — [Hooks](https://code.claude.com/docs/en/hooks)
- Hook events (34): SessionStart, Setup, UserPromptSubmit, UserPromptExpansion, PreToolUse, PermissionRequest, PermissionDenied, PostToolUse, PostToolUseFailure, PostToolBatch, Notification, MessageDisplay, SubagentStart, SubagentStop, TaskCreated, TaskCompleted, Stop, StopFailure, TeammateIdle, InstructionsLoaded, ConfigChange, CwdChanged, DirectoryAdded, FileChanged, WorktreeCreate, WorktreeRemove, PreCompact, PostCompact, PreModelSwitch, PostModelSwitch, Elicitation, ElicitationResult, SessionEnd — [Hooks](https://code.claude.com/docs/en/hooks)
- Hook stdin JSON: `session_id`, `prompt_id`, `transcript_path`, `cwd`, `scratchpad_dir`, `permission_mode`, `effort`, `hook_event_name`, plus `tool_name`, `tool_input`, `tool_use_id` for tool events; exit 0 = success (stdout parsed as JSON), exit 2 = blocking error (stderr is the reason), other = non-blocking; JSON output fields `continue`, `stopReason`, `systemMessage`, `decision: "block"`, `hookSpecificOutput.{permissionDecision: allow|deny|ask|defer, updatedInput, additionalContext, updatedToolOutput}` — [Hooks](https://code.claude.com/docs/en/hooks)
- Subagent files: `.claude/agents/*.md` (project), `~/.claude/agents/` (user), plugin `agents/`, `--agents` CLI (session only), managed settings (highest). Frontmatter: `name`, `description` (required), `tools`, `disallowedTools`, `model` (`sonnet|opus|haiku|fable|<id>|inherit`), `permissionMode`, `maxTurns`, `autoCompactWindow`, `skills`, `mcpServers` (by name or inline), `hooks`, `memory` (`user|project|local`), `background`, `omitClaudeMd`, `effort`, `isolation: worktree`, `color`, `initialPrompt`, `experimental` — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Subagent limits: nesting up to 3 layers (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`), 20 concurrent by default (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`); built-ins Explore, Plan, general-purpose, claude, statusline-setup, claude-code-guide — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Skills: `<dir>/SKILL.md` with YAML frontmatter `name`, `description`, `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork`, `agent`, `background`, `hooks`, `paths`, `shell`; locations `~/.claude/skills/`, `.claude/skills/`, nested `<subdir>/.claude/skills/`, `--add-dir` dirs, plugin `skills/`, enterprise managed dir; in `-p` mode include `/skill-name` in the prompt and Claude Code expands it — [Skills](https://code.claude.com/docs/en/skills); [Headless docs](https://code.claude.com/docs/en/headless)
- Plugins: directory with manifest `.claude-plugin/plugin.json`, components `skills/`, `agents/`, `hooks/hooks.json`, `.mcp.json`, a JS hooks module ("mod"); marketplaces are repos with `.claude-plugin/marketplace.json`; `--plugin-dir`, `--plugin-url` load for one session; install scopes user/project/local; "A cloud session … doesn't load the plugins in your local settings" — [Plugins overview](https://code.claude.com/docs/en/plugins/overview)
- MCP config: project `.mcp.json` `{"mcpServers": {"name": {"type": "http|stdio|sse|ws", "url"|"command","args","env","headers"}}}`; local/user scopes live in `~/.claude.json`; `${VAR}` / `${VAR:-default}` expansion in command/args/env/url/headers; `claude mcp add --transport http <name> <url>`, `claude mcp add-json <name> '<json>'`; `MCP_TIMEOUT` (startup ms), `MCP_TOOL_TIMEOUT`, `MAX_MCP_OUTPUT_TOKENS` (25,000 default); tool naming `mcp__<server>__<tool>` / `mcp__plugin_<plugin>_<server>__<tool>`; `claude -p`, Agent SDK and cloud sessions load project servers without prompting (block with `disabledMcpjsonServers`) — [MCP](https://code.claude.com/docs/en/mcp)
- Sandbox settings block (in settings.json): `sandbox.enabled`, `allowUnsandboxedCommands`, `failIfUnavailable`, `autoAllowBashIfSandboxed` (default true), `excludedCommands`, `filesystem.{allowWrite,denyWrite,denyRead,allowRead,disabled}`, `network.{allowedDomains,deniedDomains,allowUnixSockets,allowAllUnixSockets,allowLocalBinding,strictAllowlist,allowManagedDomainsOnly,httpProxyPort,socksProxyPort}`, `credentials` (deny/mask env vars and files), `enableWeakerNestedSandbox`; e.g. `claude --settings '{"sandbox": {"enabled": true, "allowUnsandboxedCommands": false}}'` — [Sandboxing](https://code.claude.com/docs/en/sandboxing)
- Transcripts: `~/.claude/projects/<project>/<session-id>.jsonl` where `<project>` is cwd with non-alphanumerics → `-`; "The entry format is internal to Claude Code and changes between versions, so scripts that parse these files directly can break on any release"; `CLAUDE_CODE_PROJECT_DIR_NAME` + `CLAUDE_CONFIG_DIR` pin a per-tenant project dir (v2.1.234+); `cleanupPeriodDays` default 30 — [Sessions](https://code.claude.com/docs/en/sessions)

#### Claude Agent SDK (Python/TypeScript)
- "A library that runs the Claude Code binary, with Claude Code's capabilities, such as built-in tools, permissions, sessions, and hooks"; alternatives table: CLI, Client SDK (tool runner), Managed Agents; "To drive the same agent loop from a language other than Python or TypeScript, run the CLI as a subprocess with the `-p` flag and `--output-format json`" — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- "Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication methods" — [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)
- TS `Options` fields: `maxTurns`, `maxBudgetUsd` ("Counts only the call's own spend"), `permissionMode`, `allowedTools`, `disallowedTools`, `mcpServers: Record<string, McpServerConfig>`, `agents: Record<string, AgentDefinition>`, `hooks`, `settingSources` (`[]` disables user/project/local), `resume`, `forkSession`, `outputFormat: {type:'json_schema', schema}`, `sandbox: SandboxSettings`, `plugins`, `env` (replaces subprocess env), `cwd`, `executable: 'bun'|'deno'|'node'`, `pathToClaudeCodeExecutable`, `systemPrompt: string | {type:'preset', preset:'claude_code', append?}` — [TypeScript SDK](https://code.claude.com/docs/en/agent-sdk/typescript)
- `AgentDefinition = { description; tools?; disallowedTools?; prompt; model?; mcpServers?; skills?; initialPrompt?; maxTurns?; autoCompactWindow?; background?; omitClaudeMd?; memory?; effort?; permissionMode?; … }` — [TypeScript SDK](https://code.claude.com/docs/en/agent-sdk/typescript)
- Python: `from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage`; `ClaudeAgentOptions(cwd=…, max_turns=20, setting_sources=[], env={…}, resume=…, session_store=…)`; `ClaudeSDKClient` holds a session open across turns — [Hosting](https://code.claude.com/docs/en/agent-sdk/hosting); [Cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)
- Hosting model: "When your code calls `query()`, the SDK spawns a separate `claude` CLI process and talks to it over stdio"; 1 session = 1 subprocess; "1 GiB RAM, 5 GiB disk, and 1 CPU per agent is a reasonable starting point"; SDKs bundle a native Claude Code binary pinned to the SDK version; `SessionStore` adapter mirrors transcripts to durable storage (object store/KV/DB), emits `{type:"system", subtype:"mirror_error"}` on failed batches; multi-tenant isolation via `settingSources: []`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`, per-tenant `CLAUDE_CONFIG_DIR` and `cwd` — [Hosting](https://code.claude.com/docs/en/agent-sdk/hosting)
- Known limits: "No top-level session timeout" (use `maxTurns`), memory growth over long sessions, "Large parallel-subagent fanouts can hit rate limits", "No per-subagent wall-clock deadline" (`CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS` is a stall watchdog only) — [Hosting](https://code.claude.com/docs/en/agent-sdk/hosting)
- OTEL: `CLAUDE_CODE_ENABLE_TELEMETRY=1`, `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1`, `OTEL_*_EXPORTER=otlp`, `OTEL_EXPORTER_OTLP_ENDPOINT` — [Hosting](https://code.claude.com/docs/en/agent-sdk/hosting)
- A deployable hosting cookbook exists for "local Docker, Modal, and Kubernetes" at `github.com/anthropics/claude-cookbooks/tree/main/claude_agent_sdk/hosting` — [Hosting](https://code.claude.com/docs/en/agent-sdk/hosting)

#### Claude Managed Agents (Anthropic-hosted harness)
- Status: beta; all endpoints require header `anthropic-beta: managed-agents-2026-04-01`; "enabled by default for all API accounts"; "not currently eligible for Zero Data Retention or HIPAA BAA"; MCP tunnels and "dreaming" are a narrower research preview — [Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)
- Third-party coverage dates the public launch to April 8, 2026 (not verified against an Anthropic announcement) — [sidbharath.com](https://sidbharath.com/blog/claude-managed-agents/); [weekendbyte](https://weekendbyte.com/p/anthropic-s-managed-agents-overview)
- Four primitives: Agent (model, system prompt, tools, MCP servers, skills), Environment (cloud sandbox or self-hosted), Session, Events; also "Scheduled execution: Recurring agent runs on a cron schedule through scheduled deployments" — [Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)
- REST/SDK surface: `POST /v1/agents` `{name, model:"claude-opus-5-5", system, tools:[{"type":"agent_toolset_20260401"}]}` → `{id, version}`; `POST /v1/environments` `{name, config:{type:"cloud", networking:{type:"limited", allow_package_managers:true}}}`; `POST /v1/sessions` `{agent, environment_id, title}`; `client.beta.sessions.events.send(session.id, events=[{"type":"user.message","content":[{"type":"text","text":…}]}])`; `client.beta.sessions.events.stream(session.id)`; the `ant` CLI (`brew install anthropics/tap/ant`, v1.41.0 binary) with `ant apply agent.md` and `ant beta:sessions create` — [Managed Agents quickstart](https://platform.claude.com/docs/en/managed-agents/quickstart)
- Event types: user (`user.message`, `user.interrupt`, `user.custom_tool_result`, `user.tool_confirmation`, `user.define_outcome`, `user.tool_result`), agent (`agent.message`, `agent.thinking`, `agent.tool_use` with `evaluated_permission`, `agent.tool_result`, `agent.mcp_tool_use`, `agent.custom_tool_use`, `agent.thread_context_compacted`, …), session (`session.status_running|idle|rescheduled|terminated`, `session.error` with `retry_status`, `session.usage`, `session.thread_*`), `workflow_run.*` (`created`, `status_running|idle|ended`, `error`, `phase_started|ended`), span (`span.model_request_end` with `model_usage`), `system.message`; rate limits 300 create req/min, 1,200 read req/min per org — [Managed Agents reference](https://platform.claude.com/docs/en/managed-agents/reference)
- Hard budgets: `budget: {type:"limit", max_list_cost:{amount:"125", currency:"USD"}}` on session create (amount in whole US cents as a string); priced at list rates: model tokens, "$10 USD per 1,000 searches", "Session running time, at $0.08 USD per hour"; a session at cap "pauses and goes idle" with `stop_reason: budget_reached`, emitting `session.usage` then `session.status_idle`; budget can only be attached at creation; deployments copy the budget to each run — [Budgets](https://platform.claude.com/docs/en/managed-agents/budgets)
- Multiagent: set `multiagent.type: "multiagent_20261001"`; `subagents.predefined_agents` and `workflows.predefined_agents` (up to 20 each), `inline_agents` on/off, `advisor: {type:"enabled", model}`; dynamic workflows = "The agent writes a workflow: a program that runs many agents in phases and combines their results. The server runs it in the background as one workflow run"; all agents share sandbox/filesystem/vault; each runs in its own session thread — [Multiagent orchestration](https://platform.claude.com/docs/en/managed-agents/multiagent-orchestration)
- Self-hosted sandboxes: environment `{"config": {"type": "self_hosted"}}`; worker `ant beta:worker poll --workdir /workspace` with `ANTHROPIC_ENVIRONMENT_KEY`/`ANTHROPIC_ENVIRONMENT_ID`; "Claude runs on Anthropic's side and requests tool calls. Your worker runs each call locally and posts the result back"; platform guides for AWS Lambda MicroVMs, Blaxel, Cloudflare, Daytona, E2B, Fly.io, GKE Agent Sandbox, Modal, Namespace, Superserve, Vercel; `file`/`github_repository` resources unsupported in self-hosted (only `memory_store`) — [Self-hosted sandboxes](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes)

#### OpenAI Codex CLI / SDK / config
- `codex exec "<prompt>"` is the non-interactive mode; "Progress streams to stderr, and only the final agent message goes to stdout"; `codex exec -` reads the whole prompt from stdin; default sandbox is read-only; `--sandbox workspace-write` allows edits; `--full-auto` "is no longer supported. Use `--sandbox workspace-write` or `--approve-for-me`"; `--ephemeral` skips session rollout files — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)
- `--json` emits JSON Lines with events `thread.started` (`thread_id`), `turn.started`, `item.started`/`item.updated`/`item.completed` (item object with `id`, `type`, e.g. `agent_message` with `text`, `command_execution` with `status`), `turn.completed` (`usage: {input_tokens, cached_input_tokens, output_tokens, reasoning_output_tokens}`), `turn.failed`, `error` — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)
- `-o/--output-last-message <path>` writes the final message to a file; `--output-schema ./schema.json` forces a JSON-Schema-conformant final response, e.g. `codex exec "Extract project metadata" --output-schema ./schema.json -o ./project-metadata.json` — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)
- Resume: `codex exec resume --last "<prompt>"`, `codex exec resume <SESSION_ID> [PROMPT]` (`--all` any directory), `codex exec fork <SESSION_ID> [PROMPT]`; `codex resume --include-non-interactive`; sessions persist in `~/.codex/sessions` — [CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli); [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)
- Other `codex exec` flags: `--sandbox/-s read-only|workspace-write|danger-full-access`, `--ask-for-approval/-a on-request|never`, `--approve-for-me`/`--not-so-yolo` (automatic approval review), `--dangerously-bypass-approvals-and-sandbox`/`--yolo`, `--model/-m`, `--profile/-p` (layers `$CODEX_HOME/<profile>.config.toml`), `--cd/-C`, `--config/-c key=value` (repeatable, TOML-parsed), `--skip-git-repo-check`, `--ignore-user-config`, `--ignore-rules`, `--image/-i`, `--worktree` (managed git worktree), `--add-dir`, `--search`, `--oss lmstudio|ollama` — [CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli)
- CI auth: `CODEX_API_KEY=<key> codex exec --json "…"`; "Don't set `OPENAI_API_KEY` or `CODEX_API_KEY` as a job-level environment variable in workflows that run repository-controlled code"; `openai/codex-action@v1` starts a proxy that holds the key — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)
- `codex cloud exec --env ENV_ID --attempts 1-4 [QUERY]`; `codex cloud list --json` returns `tasks[{id,url,title,status,updated_at,environment_id,environment_label,summary,is_review,attempt_total}]`; `codex apply TASK_ID` applies a cloud task's diff locally (non-zero exit if `git apply` fails) — [CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

### Inferences
- A framework templating per-agent configuration can map one abstract schema onto: Claude Code (`--settings` JSON + `--agents` JSON + `--mcp-config` + `--append-system-prompt-file` + `--max-budget-usd` + `--max-turns`, all injectable without touching the repo, especially under `--bare`); Codex (`-c key=value` overrides + `--profile` + `--output-schema` + `--sandbox`; no budget flag); OpenCode (`opencode.json` + `--agent` + HTTP server); Pi (`--system-prompt`, `-t`, `--mode json`); Gemini (`--approval-mode`, `--output-format`). The lowest common denominator is: prompt, model, system-prompt append, allowed tools/permissions, MCP servers, cwd, and a JSONL event stream.

Codex, OpenCode, Gemini and Pi report token usage but need an external supervisor to enforce budgets.
- Claude Code's `--bare` plus `--settings`/`--agents`/`--mcp-config` is the cleanest "hermetic step" story: the docs explicitly position it for CI determinism and say it will become the default for `-p`.

## KQ2. Orchestration tools built on top of Claude Code / Codex: abstractions used, and where they stop short of Airflow-like DAG orchestration (scheduling, retries, approvals, observability, pluggable runtimes)

### Takeaway
The ecosystem splits into (a) terminal/desktop "many parallel sessions in worktrees" managers (Claude Squad, Conductor, Vibe Kanban — the latter sunsetting), (b) ticket-driven schedulers (OpenAI Symphony, Gas Town/Gas City, Paperclip) that treat an issue tracker or bead store as the control plane and git branches/PRs as outputs, (c) in-harness primitives from the vendors themselves (Claude Code subagents, agent teams, background sessions, dynamic workflows, `/batch`; Managed Agents multiagent/workflow runs), and (d) loop patterns (Ralph). None expose a typed, persisted DAG with per-node retries, approval gates and artifact contracts; Symphony's own spec explicitly rules out being "a general-purpose workflow engine" and has "no database", Claude Code workflows allow "No mid-run user input", and Paperclip/Gas Town model org charts and merge queues rather than DAGs.

### Cited Findings

#### Claude Squad
- Terminal app (`cs`) managing "multiple AI terminal agents like Claude Code, Codex, OpenCode, and Amp"; tmux session per agent, git worktree per session on its own branch; keys `n` new, `N` new with prompt, `s` commit and push branch to GitHub, `c` checkout (commit + pause), `r` resume; `-y/--autoyes` experimental auto-accept; config `~/.claude-squad/config.json` with named program profiles; AGPL-3.0; prerequisites tmux + `gh` — [Claude Squad](https://github.com/smtg-ai/claude-squad)

### Inferences
- Common abstractions across orchestrators: (1) **unit of work = ticket/bead/issue**, (2) **isolation = git worktree or per-issue directory + tmux/subprocess**, (3) **output = branch/PR**, (4) **supervision = polling + stall detection + exponential backoff** (Symphony, Gas Town Witness/Deacon), (5) **merge gate = CI/merge queue** (Gas Town Refinery). None model edges between tasks as typed artifact dependencies; "dependencies" exist only as task-list blocking (Claude Code agent teams) or org hierarchy (Paperclip).
- What is missing for Airflow-like pipelines: durable DAG state (Symphony: "no database"; Claude Code workflows persist only within a session dir), approval gates mid-run (workflows: "No mid-run user input"; Managed Agents has `user.tool_confirmation` per tool call, not per node), per-node retry policies (Claude Code workflows replay from first failure; Symphony retries whole issues), typed artifacts (outputs are PR URLs, text, or JSON via `--json-schema`/`schema`), pluggable runtimes (Gas City is the only one advertising tmux/subprocess/ACP/Kubernetes providers), and cross-vendor observability (Claude Code exports OTEL; Codex/OpenCode do not document OTEL).
- Vendors are moving orchestration into the harness itself (dynamic workflows, Managed Agents workflow runs, Cursor custom subagents, Codex app-server + Symphony). A third-party DAG framework therefore competes with increasingly capable in-harness fan-out, and its value is in cross-agent, cross-run, approval-gated, cost-tracked composition.

## KQ3. State of "run Claude Code in the cloud" offerings (Claude Code on the web / cloud sessions, self-hosted environments, Managed Agents, Codex cloud, Cursor cloud agents, Devin, Jules) and their limitations for pipelines

### Takeaway
Hosted agent runs are now mainstream but are session- or task-shaped, not pipeline-shaped: Claude Code cloud sessions/routines and Codex cloud produce a session + branch/PR and are tied to consumer-plan auth; the API-first options are Claude Managed Agents (stateful sessions, budgets, server-run multiagent, self-hosted sandboxes), Cursor Cloud Agents v1 (agents + runs + artifacts, no webhooks yet), Devin v3 and Jules v1alpha (sessions with plan approval and auto-PR). ### Cited Findings
- Claude Code cloud sessions: available on Pro, Max, Team, Enterprise (premium seats); start from claude.ai/code, mobile, Desktop, `claude --cloud "task"`, or routines; "there's no separate charge for the cloud VM" but usage counts toward plan limits; "Rate limits: cloud sessions share rate limits with all other Claude and Claude Code usage… Running multiple tasks in parallel consumes more rate limits proportionately"; "repository cloning and pull request creation require GitHub" (GitLab/Bitbucket only via `CCR_FORCE_BUNDLE=1` upload <100 MB, no push back); each session runs in an isolated Anthropic-managed VM with network allowlists; GitHub credentials stay server-side behind a proxy; sessions expire when inactive and background work is "Not restored" on reopen; `--teleport <id>` pulls a session into the terminal (one-way); `--cloud` requires claude.ai sign-in (not API key, not Bedrock/Vertex); ZDR/HIPAA orgs can't use cloud features — [Claude Code in the cloud](https://code.claude.com/docs/en/claude-code-on-the-web)
- Cloud session limits: "commands Claude runs and SessionStart hooks have default timeouts", setup script cached only if it finishes in ~5 minutes; org IP allowlisting breaks Anthropic-hosted sessions; auto-fix PRs reacts to CI failures and review comments but "GitHub does not emit a webhook when the base branch advances and creates a merge conflict" — [Claude Code in the cloud](https://code.claude.com/docs/en/claude-code-on-the-web)
- Self-hosted environments (public beta, Team/Enterprise, off by default): runners (`claude self-hosted-runner`) poll Anthropic's queue over outbound HTTPS, clone repos and spawn child Claude Code processes; environment IDs `ccpool_…`; `claude -p "…" --environment ccpool_abc123 --ref main` dispatches a cloud session to your runner from a script; runner locks to one owner, `--capacity`, `--drain-grace-sec`, `--retire-at`; lease lapses ~60 s after polling stops; an autoscaling orchestrator starts on-demand runners (Kubernetes recipes exist); "The control plane remains Anthropic-hosted"; conversation content still goes to `api.anthropic.com` — [Self-hosted environments](https://code.claude.com/docs/en/self-hosted-environments)

Each task has its own workspace and keeps working while your computer is asleep"; commit or open a PR after review; the page doesn't mention a public task API, limits, or pricing — [Codex cloud](https://learn.chatgpt.com/docs/cloud); [CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

## KQ4. How people pass artifacts between agent runs today (git branches/worktrees, PRs, files, JSON summaries, session transcripts)

### Takeaway
Today's inter-run artifacts are overwhelmingly git-shaped (worktree → branch → PR), supplemented by a final JSON result object (Claude Code `result` with `session_id`, `total_cost_usd`, `usage`, `modelUsage`, `permission_denials`, `structured_output`; Codex `turn.completed.usage` + `file_change` items + `--output-schema` JSON + `-o` file), session IDs for resume/fork, and free-text messages (Claude Code cross-session `SendMessage`, Symphony ticket comments). Transcript JSONL files exist but Anthropic says their format is internal and unstable.

### Cited Findings
- Claude Code `SDKResultMessage` (success): `type:"result"`, `subtype:"success"`, `uuid`, `session_id`, `duration_ms`, `duration_api_ms`, `is_error`, `num_turns`, `result: string`, `stop_reason`, `total_cost_usd`, `usage: NonNullableUsage`, `modelUsage: {[model]: ModelUsage}`, `permission_denials: SDKPermissionDenial[]` (`tool_name`, `tool_use_id`, `tool_input`), `structured_output?`, `terminal_reason?`, `queued_turn_count?`; error variants `subtype: "error_max_turns" | "error_during_execution" | "error_max_budget_usd" | "error_max_structured_output_retries"` with `errors: string[]` and `startup_failure_reason?` (e.g. `worktree_unverified`, `worktree_resume_refused`) — [TypeScript SDK](https://code.claude.com/docs/en/agent-sdk/typescript); [Worktrees](https://code.claude.com/docs/en/worktrees)
- `SDKSystemMessage` init: `apiKeySource`, `claude_code_version`, `cwd`, `tools[]`, `mcp_servers[{name,status,source?}]`, `model`, `permissionMode`, `slash_commands`, `output_style`, `skills`, `plugins`, `plugin_errors`, `effort`, `capabilities` — [TypeScript SDK](https://code.claude.com/docs/en/agent-sdk/typescript)
- Cost semantics: "`total_cost_usd` and `costUSD` fields are client-side estimates, not authoritative billing data"; `usage` excludes subagent tokens while `total_cost_usd` and `modelUsage` include them; per-step `output_tokens` on assistant messages is a placeholder; resumed sessions report the whole session's spend (v2.1.277+) so "summing results double-counts"; `modelUsage[model]` has `costUSD`, `inputTokens`, `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens`, `costBasis: list|managed|unknown` — [Cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

- Claude Code worktrees: `--worktree <name>` creates `.claude/worktrees/<name>/` on branch `worktree-<name>`; `worktree.baseRef: "fresh"|"head"`; `.worktreeinclude` copies gitignored files (`.env`) into new worktrees; `-p` runs don't clean up worktrees; subagents with `isolation: worktree` get temporary worktrees removed when unchanged; background sessions move into their own worktree before editing (`worktree.bgIsolation: "none"` to disable); `WorktreeCreate`/`WorktreeRemove` hooks replace git logic for other VCS; isolation checks block edits/git into the main checkout — [Worktrees](https://code.claude.com/docs/en/worktrees); [Agent view](https://code.claude.com/docs/en/agent-view)
- Cross-session messaging (v2.1.224+): "A message is a piece of text one Claude writes to another, never the sender's conversation history or files"; `-p` sessions bind an inbox socket (not in `--bare`) and can accept unattended with `crossSessionInbound: accept` in `--settings`; `CLAUDE_CODE_MESSAGING_SOCKET`/`CLAUDE_CODE_MESSAGING_TOKEN` exported to hooks/Bash so scripts can post into a session; `notify_when_idle` subscription; "Plain text only", ~1M char cap — [Cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging)
- Agent teams pass state via a shared task list (`~/.claude/tasks/{team}/`, file-locked claims, dependencies) and JSON mailbox files; idle notifications include the teammate's final answer — [Agent teams](https://code.claude.com/docs/en/agent-teams)
- Dynamic workflows pass results as script variables; `agent(…, {schema})` returns validated JSON (5 retries by default, `MAX_STRUCTURED_OUTPUT_RETRIES`); "Intermediate results stay in script variables instead of landing in Claude's context"; run scripts and saved results live under the session dir in `~/.claude/projects/` — [Workflows](https://code.claude.com/docs/en/workflows)
- Codex: `codex exec --json` streams `file_change` items with `changes[{path, kind}]` and `command_execution` items with `exit_code`/`aggregated_output`; `-o` writes the final message to a file; `--output-schema` gives a typed final answer; `thread_id` enables `codex exec resume <id>`; `codex apply TASK_ID` moves a cloud diff into the local repo; Symphony's spec says "The coding agent makes ticket changes (state transitions, comments, PR metadata) through adapter-provided tools" and success is "a workflow-defined handoff state, such as a human review state" — [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode); [items.ts](https://raw.githubusercontent.com/openai/codex/main/sdk/typescript/src/items.ts); [Symphony SPEC.md](https://github.com/openai/symphony/blob/main/SPEC.md)

### Inferences
- A typed-artifact layer for pipelines can be assembled from existing primitives: (a) `structured_output`/`--output-schema` JSON as the node's declared output type, (b) `session_id`/`thread_id` as a resumable handle, (c) branch name + commit SHA + PR URL from the worktree, (d) cost/usage from `total_cost_usd`/`modelUsage` (Claude) or `turn.completed.usage` (Codex), (e) `file_change` items (Codex) or `git diff --stat` (Claude) as a files-changed manifest. ## KQ5. Sandboxing / runtime options for running these agents in containers and Kubernetes (official images, devcontainers, Anthropic sandbox runtime, Codex sandbox)

### Takeaway
No vendor ships an official "coding agent" Docker image; Anthropic provides a Dev Container Feature (`ghcr.io/anthropics/devcontainer-features/claude-code:1.0`), a reference `.devcontainer` with an egress firewall, the open-source `@anthropic-ai/sandbox-runtime` (bubblewrap/Seatbelt + proxy) that Claude Code's Bash sandbox is built on, self-hosted runners for cloud sessions, and Managed Agents self-hosted sandbox workers with guides for Modal/E2B/Daytona/Cloudflare/GKE; Codex relies on per-OS sandboxes (Seatbelt, bubblewrap, Windows) plus `codex-action` privilege-dropping strategies. Running as root, nested user namespaces and Ubuntu 24.04 AppArmor are the recurring container pitfalls.

### Cited Findings
- Dev containers: add `"features": {"ghcr.io/anthropics/devcontainer-features/claude-code:1.0": {}}` to `.devcontainer/devcontainer.json`; the feature installs latest Claude Code (pin via `npm install -g @anthropic-ai/claude-code@X.Y.Z` + `DISABLE_AUTOUPDATER=1`); persist auth with a named volume at `~/.claude` and `CLAUDE_CONFIG_DIR`; enforce policy by copying `/etc/claude-code/managed-settings.json` in the Dockerfile; reference container (`anthropics/claude-code/.devcontainer`: `devcontainer.json`, `Dockerfile`, `init-firewall.sh` needing `NET_ADMIN`/`NET_RAW`) is "a working example rather than a maintained base image"; `--dangerously-skip-permissions` is rejected when launched as root ("confirm `remoteUser` is set to a non-root account"); warning that with that flag "dev containers do not prevent a malicious project from exfiltrating anything accessible inside the container, including the Claude Code credentials stored in `~/.claude`" — [Dev containers](https://code.claude.com/docs/en/devcontainer)
- Claude Code Bash sandbox: OS-enforced around Bash/PowerShell/Monitor commands only ("Claude's file tools, MCP servers, and hooks run outside it"); Linux/WSL2 use bubblewrap + socat (+ optional seccomp filter from `npm install -g @anthropic-ai/sandbox-runtime`), macOS uses Seatbelt; network goes through a local proxy with an allowlist; default writes limited to cwd, temp dir, added dirs; `failIfUnavailable` makes startup fail if the sandbox can't start; Ubuntu 24.04 AppArmor blocks user namespaces; "Bubblewrap fails to start inside a container" is a documented troubleshooting item; "To put the tools, processes, and commands … behind one boundary, run the Claude Code process itself in a container, virtual machine, or the sandbox runtime" — [Sandboxing](https://code.claude.com/docs/en/sandboxing)
- `@anthropic-ai/sandbox-runtime` (`srt`): Apache-2.0 beta research preview "developed for Claude Code"; macOS `sandbox-exec` Seatbelt profiles, Linux bubblewrap with network namespace removed and seccomp unix-socket blocking (x64/arm64), Windows alpha via `srt-sandbox` user + WFP filter; HTTP/HTTPS and SOCKS5 proxies on the host; config `~/.srt-settings.json` with `network.{allowedDomains, deniedDomains, allowUnixSockets, allowLocalBinding}`, `filesystem.{denyRead, allowRead, allowWrite, denyWrite}`, `ignoreViolations`, `enableWeakerNestedSandbox` (Docker), `allowNestedUserNamespaces`, `credentials` masking, `network.tlsTerminate`; CLI `srt "curl example.com"`, `srt --settings path cmd`; library `SandboxManager.initialize(config); SandboxManager.wrapWithSandbox(cmd)`; wrap MCP servers as `{"command": "srt", "args": ["npx", "-y", "@modelcontextprotocol/server-filesystem"]}`; running as root needs `CAP_SETFCAP` — [sandbox-runtime](https://github.com/anthropic-experimental/sandbox-runtime)
- Agent SDK hosting: sandbox-provider checklist (who runs it, cold start, persistent storage, pricing, networking); self-hosted options "Docker, gVisor, and Firecracker"; cookbook with Docker, Modal and Kubernetes code; recommend egress proxy that injects credentials; "A minimally provisioned container runs roughly $0.05 per hour, while a single long agent session can spend dollars in tokens" — [Hosting](https://code.claude.com/docs/en/agent-sdk/hosting)
- Managed Agents cloud sandboxes vs self-hosted: cloud networking `{type:"limited", allow_package_managers:true, allowed_hosts:[…]}`; self-hosted worker needs a Linux host with `/bin/bash`, outbound HTTPS only, "Keep [the API key] off the worker host, where agent tool calls could read it"; memory stores synced to `/mnt/memory/`; GKE Agent Sandbox and AWS Lambda MicroVM guides — [Self-hosted sandboxes](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes); [Quickstart](https://platform.claude.com/docs/en/managed-agents/quickstart)
- Claude Code self-hosted environments: "the idea is the same as a self-hosted CI runner"; Kubernetes and Compose recipes on the deploy page; runner exits after sessions finish by default so "the orchestrator you deploy it under, such as Kubernetes, can restart it with a fresh disk" — [Self-hosted environments](https://code.claude.com/docs/en/self-hosted-environments)
- Codex: Linux/WSL2 sandbox requires `bubblewrap` ("uses the first `bwrap` on `PATH` and falls back to a bundled helper that needs unprivileged user namespaces"); `danger-full-access` "removes the filesystem and network boundaries"; `codex-action` `safety-strategy: drop-sudo` (default) revokes sudo, restricts root sockets under `/run` incl. Docker's, starts Codex with `no_new_privs`; `read-only` strategy still lets Codex read the API key from process memory; `unsafe` required on Windows runners — [Sandboxing](https://learn.chatgpt.com/docs/sandboxing); [codex-action README](https://github.com/openai/codex-action)
- Pi: "no built-in permission system"; README suggests containerization via a Gondolin extension, plain Docker, or OpenShell — [pi README](https://github.com/badlogic/pi-mono)
- Gas Town supports Docker, Nix, Homebrew installs; Gas City advertises a Kubernetes runtime provider — [gastown](https://github.com/steveyegge/gastown); [rywalker.com](https://rywalker.com/research/gas-city)
- OpenHands SDK: "REST-based Agent Server: Runs agents anywhere, including Docker and Kubernetes" with Docker sandboxing for remote execution — [docs.openhands.dev/sdk](https://docs.openhands.dev/sdk)

### Inferences
- For Kubernetes pipeline steps the practical pattern is one pod/container per agent run (non-root user, `ANTHROPIC_API_KEY`/`CODEX_API_KEY` injected or proxied, repo cloned into an ephemeral volume, `claude --bare -p … --output-format json --max-budget-usd … --max-turns …` or `codex exec --json --sandbox workspace-write -o result.md …`), with results captured from stdout JSON and `git push`. In-container OS sandboxes (bubblewrap) need user namespaces or `enableWeakerNestedSandbox`; otherwise rely on the pod boundary and network policy and run with `--dangerously-skip-permissions` / `--permission-prompts none` / `--approve-for-me`.
- Anthropic's own stack offers three hosting tiers with increasing control: Managed Agents cloud sandbox (zero infra), Managed Agents self-hosted worker or Claude Code self-hosted runner (your compute, Anthropic control plane), Agent SDK/CLI in your own containers (full control, you build the control plane).
